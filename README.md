# testRTC
Этот проект тестирует часы реального времен в устройствах Umka07-2

![Triol](pic/logo.png)

## Описание проекта
Автоматический цикл включения питания, сбора данных и отключения устройства.

Этот проект предназначен для автоматического тестирования устройства, которое получает питание через реле, подключённое к Raspberry Pi.

Проект полезен для долговременных тестов стабильности, проверки MAC‑адресов, времени, поведения при холодной перезагрузке и т. д.

## Схема стенда
Скрипт циклически включает питание в Umka7-02 через реле, ждёт загрузки устройства, получает от него данные по SSH, затем отключает питание и делает паузу перед следующим циклом.

```
 ┌──────────────────────┐
 │   Блок питания 24 В  │
 └───────────┬──────────┘
             │ 24V
             ▼
      ┌──────────────┐
      │   Реле (НО)  │
      │  КОНТАКТЫ    │
      └──────┬───────┘
             │ 24V OUT
             ▼
      ┌────────────────┐
      │      УМКА      │
      │  Питание 24 В  │
      │      SSH       │
      └───────┬────────┘
              ▲
              │ SSH
              │
 ┌────────────────────┐
 │    Raspberry Pi     │
 │                    │
 │  GPIO ──► Драйвер ──► Катушка реле
 │                    │
 │     SSH      ───────► к УМКА
 └────────────────────┘
```

## Как работает цикл?
Каждый цикл выполняет следующие шаги:
- Включение реле (подача питания на устройство).
- Ожидание 2 минуты, чтобы устройство полностью загрузилось.
- Получение данных по SSH:
текущая дата/время устройства,
MAC‑адрес первого сетевого интерфейса.
- Запись результата дописывается в файл results.log
Формат строки:
```
номер_цикла; дата; mac
```
- Отключение реле (снятие питания).
- Ожидание 28 минут перед следующим циклом.
Цикл повторяется бесконечно.

## Особенности
- Устройства всегда имеют статический адрес - 192.168.8.3
- Креды для входа по SSH - root [без пароля]

## Требования
- Raspberry Pi (проверено на Raspberry Pi 4)
- Python 3
- Модуль RPi.GPIO (требуется доступ в Интернет)
- Доступ по SSH к тестируемому устройству
- Реле, подключённое к BCM-18 (физический пин 12), включенное состояние по LOW
- Виртуальное окружение

## Подготовка
Создать виртуальное окружение и активировать его:
```
python3 -m venv venv
source venv/bin/activate
(deactivate -- выйти из окружения)
```
Установить зависимости:
```
pip list
pip install RPi.GPIO 
```

## Запуск
Создать новую tmux‑сессию (для долгих тестов):
```
tmux new -s testRTC
```
Активировать виртуальное окружение внутри tmux и запустить тест:
```
source venv/bin/activate 
python3 testRTC.py 
```
Отсоединиться от сессии, оставив скрипт работать:

[Ctrl + B], затем D 

Вернуться в сессию позже:
```
tmux attach -t testRTC 
```

## Результаты
Все результаты сохраняются в файл results.log.
Каждая строка — один тест:
```
1; Wed Feb 18 11:04:46 UTC 2026; 7a:86:d3:a4:0f:b6
2; Wed Feb 18 11:34:52 UTC 2026; 7a:86:d3:a4:0f:b6
... 
```

## Настройки
В скрипте можно изменить:
- IP‑адрес устройства
- SSH‑логин
- длительность включения
- длительность выключения
- путь к лог‑файлу
- GPIO‑пин реле
